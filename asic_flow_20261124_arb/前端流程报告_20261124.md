# 2 通道 AXIS 仲裁 + DES SoC 前端流程报告（DC / PT / Formality）

日期：2026-11-24  
工具：DC O-2018.06-SP1、PrimeTime O-2018.06-SP1、Formality O-2018.06-SP1  
工艺库：Nangate45 `NangateOpenCellLibrary_typical`（只有 typical）  
顶层：`des_arb_soc_top`  
结论：**100MHz 单角 setup/hold 全收敛；250MHz reg2reg 收敛，但 AXIL 读数据输出路径有 52 条 setup 违例**。Formality 两版均 **4,784/4,784 通过**。

---

## 1. 流程与关键修正

- **必须用 `analyze → elaborate → link`，不能用 `read_file`**。参数化实例（`sync_fifo`、`axis_arb2`、`axis_arb_regs`）用 `read_file` 会被静默丢成空引用，面积/时序报告看起来正常但少整块逻辑。
- 综合后加实例自检：
  - `sync_fifo=2`
  - `axis_arb2=1`
  - `axis_arb_regs=1`
- `dc_arb.tcl` 内 `set_svf`，Formality 读同一个 SVF，避免 FM-203。
- PT 的 1 条 error 是 `PT-063: Library Compiler executable path is not set`，属工具环境提示，不影响时序报告。

## 2. 100MHz（10ns）结果

### 2.1 面积

| 指标 | 数值 |
|---|---|
| Cells | 26,467 |
| Sequential (DFF) | 4,633 |
| Combinational area | 23,320.49 µm² |
| Noncombinational area | 22,339.21 µm² |
| **Total cell area** | **45,659.70 µm²** |

层次拆分：

| 模块 | 面积 (µm²) | 占比 |
|---|---|---|
| `u_des/u_axis/u_des`（DES 16 级流水） | 24,207.86 | 53% |
| `u_arb/u_fifo0`（16×65 同步 FIFO） | 7,777.57 | 17% |
| `u_arb/u_fifo1`（16×65 同步 FIFO） | 7,776.78 | 17% |
| 其余（仲裁逻辑、AXIL 寄存器、边带 FIFO、复位同步等） | ~5,897 | 13% |

**关键观察**：Nangate45 没有 SRAM 宏，两个 16×65 FIFO 被综合成触发器阵列，合计 **15,554 µm² / 34%**。这是“ASIC 里小存储用触发器堆”的真实代价，也是面试可讲的面积取舍点。

### 2.2 时序

| 指标 | 数值 |
|---|---|
| DC setup WNS / TNS | 0.00 / 0.00（0 违例） |
| DC hold WNS / TNS | 0.00 / 0.00（0 违例） |
| PT clk setup 违例 | 0 |
| PT clk hold（reg2reg）违例 | 0 |
| PT reg2reg 最差 slack | **+7.4234 ns** |
| PT async_default hold | 227 条 removal，slack ≈ −0.10 ns |

最差 reg2reg 路径：
- Startpoint：`u_des/u_axis/u_des/pipe_stages[15].u_round/valid_o_reg`
- Endpoint：`u_arb/ch1_stall_o_reg[31]`
- 这是“DES 输出 valid → 仲裁器 stall 计数器”的使能路径，不是 DES 数据通路。

removal 227 条：复位同步器 `rst_sync_r_reg` 的 CK→Q 与下游异步复位端同沿检查，属于 PT 同沿保守悲观；物理上复位撤销要到下一拍才被采样。与 11-08 的 243 条同一类，**刻意保留可见，不 waive**。

### 2.3 功耗（估算，非签核）

| 指标 | 数值 |
|---|---|
| Dynamic | 3.0336 mW |
| Leakage | 922.27 µW |
| Total | 3.9559 mW |
| clock_network | 0.00%（理想时钟，未 propagate） |
| register | 84.30% |

边界：未读 SAIF、WLM 无真实线载、理想时钟，只能当相对趋势，不能当签核功耗。

## 3. 250MHz（4ns）结果

### 3.1 面积

| 指标 | 数值 |
|---|---|
| Cells | 26,958 |
| Sequential (DFF) | 4,633 |
| Total cell area | 46,135.04 µm² |

比 100MHz 大约 **+1.0%**（26,958 vs 26,467 cells），DFF 数不变。

### 3.2 时序

| 指标 | 数值 |
|---|---|
| PT clk setup 违例 | **52** |
| PT clk setup WNS | **−0.96 ns** |
| PT clk hold（reg2reg）违例 | 0 |
| PT reg2reg 最差 slack | **+1.5279 ns（MET）** |
| PT async_default hold | 184 条 removal |

**违例位置**：`s_axil_arb_rdata[31:0]` 输出端口，slack −0.96 ~ −0.93 ns，共 52 条。  
这是 **AXI4-Lite 读数据 mux → 输出端口** 的组合路径（仲裁器计数器/配置寄存器 → `rdata` mux → 2.0ns 输出预算），不是 DES 流水线，也不是 reg2reg。

**结论**：
- 250MHz 下 **DES + 仲裁器 reg2reg 仍收敛（+1.53ns）**；
- 失败的是 **AXIL 读数据 IO 输出路径**；
- 不能报“250MHz 全签核”。

**修法**（下一步可选）：
1. 在 `axis_arb_regs.v` 给 `s_axil_rdata` 加一级寄存器输出（AXI-Lite 允许 1 拍读延迟），把 mux 从 IO 路径里拿掉；
2. 或把 250MHz 的 IO 输出预算从 2.0ns 放宽到实际系统值；
3. 或只报 reg2reg，不报 IO 路径，但面试要主动说明边界。

## 5. 边界（面试必须主动说）

- Nangate45 只有 **typical** 单角，没有 SS/FF；用 `set_timing_derate` 也只是近似，不是签核。
- 理想时钟、WLM、pre-CTS；没有真实时钟树和 SPEF。
- IO 2.0ns 是占位预算，真实值应来自系统接口。
- 无 DFT/scan、无 P&R、无 UPF、无门级 SDF 后仿。
- 100MHz 的 227 条 / 250MHz 的 184 条 removal 是同沿保守悲观，已文档化，不 waive。
- 功耗未读 SAIF，只能报相对趋势。

## 6. 面试 60 秒口径

> “我把 2 通道仲裁器和 DES 集成后跑了 DC→PT→Formality：100MHz 单角下 setup/hold 全收敛，reg2reg 最差 +7.42ns；面积 45,660 µm²、4,633 个 DFF，其中两个 16×65 FIFO 占 34%，因为 Nangate45 没有 SRAM 宏，小 FIFO 只能堆触发器。250MHz 下 reg2reg 还有 +1.53ns，但 AXIL 读数据输出 mux 有 52 条 IO 路径违例，WNS −0.96ns——这说明瓶颈在控制面读 mux，不在 DES 数据通路。Formality 两版都是 4,784/4,784。边界是 typical 单角、理想时钟、pre-CTS，不是签核。”
