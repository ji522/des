## 三、必须知道的几个坑（读报告时别被数字误导）

### 1. “关键路径 +4.99 ns”不是数据通路

DC/PT 报出的最差路径是 **`m_axis_tready`（输入端口）→ `s_axis_tready`（输出端口）** 的组合直通，
经过 16 级 ready 链（18 级门），逻辑延时只有 0.91 ns；剩下的 4 ns 完全是 SDC 里假设的
`set_input_delay 2.0` + `set_output_delay 2.0`。

真正的寄存器到寄存器最差路径是 **1.918 ns**（裕量 +7.9441 ns），所以 100 MHz 大约有 5 倍余量。
写简历/汇报时应引 reg2reg 数字，不要引 +4.99。

### 2. 771 条 hold 违例是 pre-CTS 假违例

最差 **−3.8 ps**，768 条是 `key_ram_reg[*][*]` 的寄存器自环（Q → 一级 AOI → 自己 D）。
根因是 `set_clock_uncertainty 0.10` 同时对 setup 和 hold 生效，而时钟还是理想零偏斜。
**这不是 RTL/网表 bug**，CTS 后插几个缓冲即可，或者把 uncertainty 拆成
`-setup 0.10 / -hold 0.03~0.05`。

### 3. 只有 typical 一个 corner

`pdk/nangate45` 只有 `NangateOpenCellLibrary_typical.db`，没有 slow/fast 库，也没有
`set_operating_conditions` / OCV derate。**当前结果是 DC 阶段的估算，不是签核级时序。**
真签核要 SS 角跑 setup、FF 角跑 hold。

### 4. 复位完全没有时序检查

`des.sdc` 里 `set_false_path -from [get_ports rst_n]` 把复位路径整体摘掉了。PT 的
`report_analysis_coverage` 显示：

```
recovery   1265 个端  0 met  0 violated  1265 untested (100%)
removal    1265 个端  0 met  0 violated  1265 untested (100%)
setup      2065 / 2065 met (100%)
```

`rst_n` 直接接 1265 个异步清零/置位端、1245 个负载，RTL 里**没有复位同步器**。
如果这块要上台面讲，建议补 2 级复位同步，并对同步器输出做 recovery/removal 检查。

### 5. 约束是占位值

- 输入驱动没建模：没有 `set_driving_cell` / `set_input_transition`，输入斜率是理想的 0。
- `set_input_delay 2.0` / `set_output_delay 2.0` 是拍脑袋的，对所有 AXI 握手信号一视同仁。
- 输出负载统一 `set_load 0.02`（20 fF）。
- 没有 `set_max_transition` / `set_max_capacitance`，`clk`(2065 负载) 和 `rst_n`(1245 负载)
  高扇出网只靠 DC 的 TIM-134 默认 modelling。

### 6. 网表里 `encrypt_i_BAR` 是正常现象

DC 做了边界反相优化：取 `encrypt_r_reg` 的 `QN` 接到子模块，端口被重命名成 `encrypt_i_BAR`，
内部 `assign encrypt_i = encrypt_i_BAR;`。Formality 已证明功能等价（2173 点全过），
只是调试/ECO 时看到这个端口名别慌。

## 四、RTL 检查结论（综合前已确认）

- `des_axil_regs.v` CTRL 读回已是**精确 32 位**：`{29'h0, 1'b0, enable_r, encrypt_r}`，
  bit0=MODE、bit1=ENABLE、bit2=0（CLR_ERR 只写），旧版的 33 位截断 bug 确实已修。
- `des_soc_top.v` 在 `ENABLE=0` 时 `s_axis_tready` 被门控为 0，不会吞数据。
- 没有 latch、没有组合环、没有多驱动；5 个时序块全部 `posedge clk or negedge rst_n` 带复位。
- 唯一 RTL 告警：`des_pipeline_fb.v:62` 有符号/无符号宽度转换（VER-318），无害；
  想消掉可写成 `!encrypt_i ? (5'd15 - i[4:0]) : i[4:0]`。
- `key_ram_gen` 的 16×48 键表被综合成 **768 个触发器**（Nangate45 没有 SRAM 宏），
  占全部触发器约 37%，也是 hold 违例集中的地方。

## 六、建议的下一步（如果要继续往前端签核走）

1. 给 `pt.tcl` / `dc.tcl` 增加 reg2reg、in2reg、reg2out、in2out 分类时序报告，别只看一条 I/O 直通。
2. 拆分 setup/hold 的 clock uncertainty，CTS 后 `set_propagated_clock` + hold fix。
3. 补 slow/fast 两个 corner（有 `.lib` 就能用 LC 编 `.db`）。
4. 补 `set_driving_cell` / `set_max_transition` / `set_max_capacitance`，把 reset 树也管起来。
5. 想真正签核，把 `rst_n` 的 false path 换成复位同步器 + recovery/removal 检查。
